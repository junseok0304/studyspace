# StudySpace 최종 PRD

버전: 6.0 · 작성일: 2026-09-30 · 상태: 제품 범위 확정 / 출시 검증 진행 전

후속 진행 기록: 같은 날 Gemini 실제 생성과 브라우저 표본 테스트를 수행했다. 최신 결과 및 남은 검증 범위는 [AI 검증 기록](AI-VALIDATION.md)을 따른다. 아래 코드 점검 표와 “이번 확인 범위”는 최초 PRD 작성 시점의 기준선이다.

## 1. 최종 결정

현재 구현된 화면과 사용자 동선을 완성형 기획으로 확정한다. 새로운 화면이나 학습 기능을 추가하는 단계는 종료한다. 남은 개발은 **현재 기능의 AI 실연결, 동작 검증 및 발견된 결함 수정, 미사용 코드·보일러플레이트 리팩터링** 세 가지로 한정한다.

이 문서는 `PRD.md` v5.1과 `PRD-UI-REFINEMENT.md` v1.0의 기능 계획·우선순위·완료 기준을 대체한다. 과거 문서는 변경 이력이며, 그 안의 미완료 항목을 자동으로 개발 범위에 포함하지 않는다. 기존 진행률 수치는 폐기한다. 현재 화면이 기획상 최종이라는 결정과, 모든 기능이 실환경에서 검증됐다는 판단은 구분한다.

## 2. 제품 목표와 범위

대학생이 학기·과목별로 노트, 강의자료, 녹음을 보관하고, 현재 노트와 분석된 자료를 바탕으로 인포그래픽·퀴즈·플래시카드를 이용하는 학습 공간이다. 읽기와 학습에 집중할 수 있는 현재의 간결한 화면을 유지한다.

다음 항목은 최종 제품 개발 범위에서 제외한다.

- STT 및 음성 전사 기반 학습. 후속 인터페이스나 비활성 기능을 준비하는 것도 요구하지 않는다.
- 대시보드를 네 개의 작업 카드로 재구성하는 이전 계획. 현재의 네 개 요약 지표 카드는 이 계획과 별개이며 유지한다.
- 별도 스피드 퀴즈·퀴즈 생성 메뉴, AI 정리와 연습의 분리, 전체 생성 작업 화면.
- 별도 요약·AI 노트·마인드맵·시험 대비 화면 및 AI 산출물 파일/SVG/PNG 저장 UI의 재도입.
- 녹음 파형 드래그 구간 선택, 첨부자료의 생성 포함 체크박스·분석보기 UI의 재도입.
- 새로운 입력 형식, 모바일 앱/PWA, 신규 대시보드나 전면 디자인 개편.

현재 노트·계정 데이터 내보내기 등 이미 존재하는 기능은 AI 산출물 다운로드 제거와 구분한다. 기존 데이터와 사용 중인 API는 참조·호환성을 확인한 뒤에만 정리한다.

## 3. 확정된 화면과 동작

| 영역 | 유지할 최종 동작 |
| --- | --- |
| 공통 탐색 | 학습 현황·수업노트·작성 팁, 학기 선택, 과목 목록과 관리. 과목·노트·탭 맥락이 유지되어야 한다. |
| 대시보드 | 노트 열람률·최근 7일·수강 과목·쌓아온 노트 요약 지표와 활동·오늘 수업·과목별 노트·이어서 공부하기·퀴즈 기록·복습 카드. 실제 저장 데이터와 연결된 행동을 제공한다. |

| 노트 읽기 | 카드 테두리로 감싸지 않은 Markdown 문서. 제목·메타정보와 본문 시작선 정렬, 중복 제목·AI 메타데이터 비노출. |
| 노트 편집 | 편집 버튼 자리의 저장 버튼, Cmd/Ctrl+S로 저장 후 읽기 복귀. 변경이 없으면 서버 저장 없이 읽기 복귀. 3분 간격 로컬 초안 백업, 복구 시 편집 진입, 저장 충돌·실패 시 작성 내용 보존. |
| 강의자료 | 노트별 PDF·PPTX·HWP·PNG, 파일당 최대 50MB, 선택 및 드래그앤드롭 업로드. 업로드 후 현재 화면 유지, 분석 및 짧은 요약을 파일명 아래 표시. 분석 완료 자료는 해당 노트의 AI 입력에 기본 포함. |
| 녹음 | 과목 단위 보관·같은 과목 모든 노트에서 공유, 다른 과목과 분리. 이름 옆 연결 노트 드롭다운 변경을 자동 저장. 명시적 시작 시에만 마이크 사용, 한 건 최대 60분. |
| 녹음 중 | 같은 페이지의 탭 이동에도 녹음 유지, 녹음 시작 노트 기억 및 진행 시간 표시. 녹음 화면은 노트 본문 없이 집중형으로 표시한다. 페이지 종료 후 녹음 지속은 요구하지 않는다. |
| 녹음 재생 | 저장된 파형·클릭 탐색·배속·재생바 기준 확대/축소. 기본 파형은 녹음 전체 길이이며 표시 시간은 실제 재생 길이 기준. 새로고침 후 파일·파형·연결 노트 복원. |
| AI 학습 | 단일 상위 탭 아래 인포그래픽·퀴즈·플래시카드 세 탭. 현재 노트의 저장 결과를 즉시 조회하고, 유효한 결과가 없으면 생성. 인포그래픽 페이지 이동, 퀴즈 힌트·오답 기록·오답 다시 풀기, 플래시카드 뒤집기·복습 기록 유지. |
| 작성 팁 | 현재 콘텐츠와 읽기 구조 유지. 자연스러운 한국어, 기본 버튼 배경 투명, 호버·선택 상태 구분. |
| 타이머 | 현재 집중/휴식 UI, 시간 조정·일시정지·초기화·원형 진행 표시 유지. 실행 중 문서 제목 우선 적용, 반대 모드 한 번 자동 실행 후 정지. |
| 계정·설정 | 현재 가입·로그인·인증·재설정·카카오·마이페이지·학교 연동·약관·개인정보 화면 유지. 데이터 분리와 저장 기능을 검증한다. |

## 4. 코드 점검 결과

2026-09-30 작업 트리 기준이다. 아래의 “구현”은 코드 존재를 뜻하며 실제 제공자·브라우저 검증 완료를 뜻하지 않는다.

| 확인 사항 | 근거와 판단 |
| --- | --- |
| AI 학습 통합 | `index.html`, `learning-workspace.js`에 세 하위 탭과 노트 버전별 조회·생성 연결이 있다. 최종 화면 구성에 도달했다. |
| 모듈 분리 | `study.js`는 492줄이며 dashboard/attachments/recording/generation/quiz/flashcards 등으로 분리되어 있다. 과거의 1,070줄 단일 파일 문제를 그대로 미구현으로 계산하지 않는다. |
| 스크립트·CSS | `app.js`는 module로 로드된다. `workspace-refinement.css`는 7개 컴포넌트 CSS를 순서대로 import한다. 파일 분리만으로 중복 규칙·상태 의존성 제거까지 완료됐다고 간주하지 않는다. |
| 실제 AI 호출 | `GeminiGenerator`, `GenerationWorker`, `QuizController`, `FlashcardController`에 실호출 경로가 있다. 설정 기본값은 모의 모드이며, 실제 세 출력의 품질·실패 처리 검증은 남아 있다. |
| 자료 분석·요약 | `AttachmentAnalysisWorker`는 문서 추출, PNG 분석, 파일별 요약을 연결한다. PNG와 요약은 Gemini를 직접 호출하며 학습 생성의 mock 분기와 동일하게 보호되지 않는다. 모의 모드의 외부 호출 정책을 통일해야 한다. |
| 결과 재사용 | 프론트 결과 조회 키가 주로 노트 ID·버전이다. 노트 본문은 그대로이고 첨부만 추가·삭제·분석 완료된 경우 결과가 최신 입력을 반영하는지 보완이 필요하다. |
| 녹음 소유권 | `RecordingController`에 과목별 목록, 같은 과목 노트 연결 검증, 파형 저장 경로가 있다. 과거의 노트 귀속 설계는 최종 요구가 아니다. 실제 마이크·새로고침·과목 전환 검증은 별도 수행한다. |
| 대시보드 연결 | `DashboardController`와 `dashboard.js`에 퀴즈·복습 대상 연결이 있다. 복습 대상 노트의 최신 버전 덱이 실제 복습 예정 덱과 다른 경우까지 점검해야 한다. |

판정: **제품의 화면·주요 기능 골격은 최종 방향에 도달했다. 실서비스 완료 판정은 아직 하지 않는다.** 남은 항목은 새 기능 확장이 아니라 아래 세 트랙의 마감 작업이다.

## 5. 남은 작업 A — 현재 기능의 AI 실연결

- [ ] 서버 키·모델·인증 조건을 점검하고, 설정 전환으로 인포그래픽·퀴즈·플래시카드 및 자료 분석·요약을 실제 제공자에 연결한다. 비밀키를 브라우저·로그에 노출하지 않는다.
- [ ] 모의 모드는 외부 유료 호출을 하지 않고 모의 결과임을 표시한다. 실제 모드는 제공자 실패를 모의 성공으로 숨기지 않는다. 기존 모의 결과가 실제 활성화 이후에도 그대로 재사용되는 경우를 처리하되 학습 기록은 보존한다.
- [ ] 입력을 현재 사용자·과목·노트와 분석 완료 첨부로 제한한다. 첨부 추가·삭제·분석 완료 및 노트 수정에 맞춰 결과의 유효성을 판단한다.
- [ ] 같은 입력 재열람은 저장 결과를 재사용한다. 연속 클릭·동시 탭·재시도에서 중복 생성과 중복 과금을 방지하고, 명시적 재생성은 구분한다.
- [ ] 실제 응답의 구조·내용·근거를 검증한다. 인포그래픽 분량과 페이지, 퀴즈 정답·힌트·해설, 플래시카드 앞뒤 내용이 원문과 일치해야 한다.
- [ ] 네트워크 오류·시간 초과·할당량·잘못된 응답·분석 실패를 구분해 표시하고 재시도할 수 있게 한다. 사용량 기록 실패가 성공/실패 상태를 왜곡하지 않게 한다.

완료 증거: 세 학습 출력과 자료 요약의 실제 성공 결과, 재조회 결과, 실패·재시도 결과, 사용량 기록. PDF/PPTX/HWP/PNG 실제 표본을 사용하며 민감한 사용자 자료는 검증 자료로 임의 전송하지 않는다.

## 6. 남은 작업 B — 기존 기능 검증과 결함 수정

- [ ] 브라우저에서 로그인 → 과목 → 노트 작성·저장·읽기 → 자료 업로드 → AI 학습 → 퀴즈·복습 → 대시보드 복귀의 전체 흐름을 확인한다.
- [ ] 변경 없는 저장, 단축키, 저장 중 추가 편집, 초안 복구, 저장 실패·충돌, 삭제·복원에서 데이터 손실이 없는지 확인한다.
- [ ] 노트 목록 접힘, 모든 탭에서 노트·과목 변경, 빠른 연속 전환에서 이전 요청의 결과가 다른 노트 화면을 덮지 않는지 확인한다.
- [ ] 파일 유형·50MB 경계·드래그 업로드·분석 실패·재시도·새로고침과 파일별 요약 표시를 확인한다.
- [ ] 실제 마이크로 녹음·저장·재생·파형 복원·배속·확대·연결 노트 변경을 확인한다. 권한 거부·저장 실패·60분 제한·브라우저 코덱 차이와 같은 과목 공유/다른 과목 분리를 점검한다.
- [ ] 퀴즈 답변·힌트·오답 재시도와 플래시카드 복습 기록이 새로고침 후 보존되고 대시보드 수치·목표와 일치하는지 확인한다. 이전 노트 버전의 복습 예정 카드도 확인한다.
- [ ] 타이머 탭 전환·제목 우선권·일시정지·자동 한 사이클 전환, 작성 팁 및 계정 화면의 버튼 연결을 확인한다.
- [ ] 사용자 간 접근 차단, 삭제·용량 처리, 인증·학교 연동 오류, HTML/Markdown 안전 렌더링을 확인한다.
- [ ] 현재 레이아웃을 유지하면서 데스크톱·좁은 화면·키보드·확대 보기에서 잘림·겹침·포커스 문제만 수정한다. 새로운 반응형 화면 기획으로 확장하지 않는다.
- [ ] 전달할 실행 환경에서 최신 코드가 실행되는지, DB·첨부·녹음이 재시작 후 유지되는지, 백업 복원이 가능한지 검증한다.

완료 증거: 브라우저/환경·시나리오·실행일·예상/실제 결과·실패 수정 후 재검증을 기록한다. 단위 테스트나 기존 검증 문서를 실제 브라우저 확인으로 대체하지 않는다.

## 7. 남은 작업 C — 미사용 코드·보일러플레이트 정리

- [ ] 제거된 메뉴·작업 목록·다운로드·구간 선택·STT 관련 잔여 코드와 설정의 실제 참조를 조사한다. 참조 없는 것만 제거하고 보존 데이터에 필요한 경로는 구분한다.
- [ ] 과거 AI 종류·API·시각화 유틸리티는 내부 호출·자료 요약·기존 데이터 읽기 여부부터 확인한다. UI가 없다는 이유만으로 삭제하지 않는다.
- [ ] 기능 모듈의 요청·로딩·오류·정리 패턴, DOM 헬퍼, 퀴즈/카드 반복 목록 코드의 중복을 필요한 범위에서 통합한다. 이미 완료한 모듈화를 다시 대규모 재작성하지 않는다.
- [ ] CSS의 중복 선택자·무효 오버라이드·미사용 클래스와 JS의 미사용 import·전역 연결·이벤트 리스너·폴링 수명을 정리한다. 현재 시각 결과와 탐색 동작을 보존한다.
- [ ] 실제 동작과 맞지 않는 오래된 문구·주석·README를 정리하고, 기능 단위 회귀 테스트 및 빌드로 확인한다.

기존 작업 트리의 다른 수정은 보존한다. 삭제 전 참조 조사 → 작은 단위 변경 → 회귀 검증 순서로 진행하며, 새 프레임워크 도입이나 구조 자체를 위한 전면 재작성은 하지 않는다.

## 8. 최종 완료 기준과 이번 확인 범위

세 트랙의 체크리스트가 검증 증거와 함께 완료되고, 데이터 손실·잘못된 노트 연결·사용자 간 노출·중복 유료 생성·핵심 동선 차단 결함이 없어야 최종 완료다. 남은 외부 검증이 있으면 “완료”나 임의의 99%로 보고하지 않는다.

이번 문서 작성 시 확인:

- `npm test`: 27개 통과.
- `gradle test --no-daemon`: 성공.
- 코드·설정·화면 마크업과 기존 PRD의 차이를 점검했다.
- 실제 Gemini 호출, 마이크 녹음, 브라우저 전체 흐름, 배포/복원은 이번 점검에서 수행하지 않았다. 이 문서는 해당 검증을 완료했다고 주장하지 않는다.

개발 종료 조건은 **현재 화면 유지 + 실제 AI 연결 완료 + 검증 통과 + 코드 정리 완료**이며, 이 조건 뒤에 이전 PRD의 신규 기능 개발을 이어 붙이지 않는다.
