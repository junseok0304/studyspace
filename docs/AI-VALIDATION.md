# Gemini 학습 기능 검증

실행일: 2026-09-30 · 환경: localhost:8091 / Gemini 실제 모드

## 확인 결과

사용자가 지정한 계정의 기존 강의노트와 분석 완료 PDF 2개를 사용했다. 원본 노트·파일은 변경하거나 삭제하지 않았으며 새 AI 결과와 테스트 풀이·복습 기록만 저장했다. 계정 자격증명과 실제 자료 본문은 이 문서에 기록하지 않는다.

| 기능 | 실제 확인 |
| --- | --- |
| 요점 정리 | Gemini 결과 3,619자 생성·저장·API 재조회, 첨부 2개 포함 |
| 인포그래픽 | Gemini 결과 3,413자 생성·저장, 화면에서 6페이지 렌더링 및 다음 페이지 전환 |
| 퀴즈 | 3문항 생성·재조회, 노트 및 PDF 내용 기반 문제·힌트·출처 확인 |
| 퀴즈 학습 | 브라우저에서 답변 저장·제출·2/3 채점, 오답 1개 재출제 후 정답 제출 |
| 플래시카드 | 8장 생성·재조회, 브라우저에서 앞뒤 전환·출처 확인·복습 기록 저장 |
| 파일별 요약 | 기존 실패 PDF 2건을 브라우저에서 재시도, 각 파일명 아래 실제 요약 표시 |

학습 결과는 모두 `mockResult=false`, 제공자 설정은 `gemini-3.6-flash`였다. 모델 이용 가능 여부는 계정별로 다르므로 실행 환경에서 설정값을 확인한다. 테스트는 샘플 기능 검증이며 모든 생성 결과의 사실 정확성을 보장하지 않는다.

최종 빌드로 서버를 재시작한 뒤 저장된 인포그래픽과 오답 재풀이 결과(1/1 정답, 진행률 100%)가 복원되는 것을 브라우저에서 다시 확인했다.

자동 검증: `npm test` 29개 통과, `npm run build` 성공, `gradle test bootJar --no-daemon` 성공. `npm audit --omit=dev --audit-level=high`는 실행 시점에 보고된 취약점 0개였으며 전체 시스템 감사를 대체하지 않는다.

## 반영한 보완

- 퀴즈·플래시카드에 JSON Schema를 지정하고 응답 구조·정답 인덱스를 검증한다.
- 짧은 파일 요약의 출력 토큰 상한을 확장하고 키·모델·한도·시간 초과 오류를 구분한다. Gemini의 토큰 상한에는 추론 토큰도 포함될 수 있다. [공식 안내](https://ai.google.dev/gemini-api/docs/generate-content/thinking)
- 실제 모드에서는 이전 모의 결과를 현재 결과로 자동 선택하지 않는다.
- 자료 목록을 읽은 뒤 AI 학습을 열어 첨부 입력 누락을 방지한다.
- 파일 요약 실패에 명시적 재시도 버튼을 제공하고, 실패 상태의 무한 폴링을 제거한다.
- 업로드 후 표시되지 않는 별도 SUMMARY 작업을 추가 생성하지 않는다. 파일별 요약은 기존 분석 워커에서 수행한다.
- 모의 모드의 자료 요약·PNG 분석은 외부 호출을 하지 않는다.
- 같은 화면의 중복 생성 클릭을 제한하고 생성/조회 도중 노트 전환 시 이전 결과의 화면 덮어쓰기를 방지한다.
- 실패 후 탭 재진입으로 다시 시도할 수 있으며, 채점 완료 진행률은 100%로 표시한다.

출력 구조는 [Gemini JSON Schema 문서](https://ai.google.dev/api/generate-content#v1beta.GenerationConfig)를 참고했다. 키와 제공자 원문 오류는 클라이언트에 전달하지 않는다.

## 재현

1. `.env`에서 실제 모드를 설정하고 서버를 재시작한다. `.env`와 실행 DB는 커밋하지 않는다.
2. 테스트 계정으로 로그인해 실제 노트와 분석 완료 자료가 있는지 확인한다.
3. `scripts/ai-live-check.mjs`는 환경변수 `TEST_EMAIL`, `TEST_PASSWORD`를 사용한다. 기본 실행은 목록 확인이며 `TEST_NOTE_ID`와 `--generate`를 함께 지정해야 실제 생성·저장을 실행한다. 자격증명을 파일에 적지 않는다.
4. 강의자료에서 파일 요약을 확인하고 AI 학습 세 탭에서 저장 결과와 학습 동작을 확인한다.

실제 생성 테스트는 유료 호출과 새 결과 저장을 수반한다. 반복 실행 시 새 결과가 추가되므로 재조회만 할 때 `--generate`를 사용하지 않는다.

## 검증 한계와 남은 항목

- 이번 실제 파일 테스트는 PDF 2개 기준이다. PNG·PPTX·HWP의 다양한 실제 표본, 장시간 부하, 제공자 장애 주입은 별도 점검 대상이다.
- 노트 버전과 실행 모드는 결과 재사용에 반영된다. 첨부만 추가·삭제·재분석한 경우 기존 결과를 자동 무효화하는 입력 지문 관리는 아직 별도 보완이 필요하다. 현재는 다시 생성/새 퀴즈/새 카드 버튼으로 갱신한다.
- 단일 화면 중복 클릭과 같은 요청 ID의 저장 재사용은 지원하지만 여러 브라우저의 서로 다른 요청 ID에 대한 유료 호출 통합은 보장하지 않는다.
- 기존 자동 테스트와 이번 표본 검증을 전체 PRD의 운영·배포 검증 완료로 해석하지 않는다.
