# StudySpace UI 개선 및 Gemini·녹음 기능 개발 PRD

> 과거 UI 개선안입니다. [최종 PRD v6.0](PRD-FINAL.md)을 따릅니다. 특히 4개 작업 카드 재구성 계획은 폐기되었으며 현재 화면을 최종 기획으로 확정했습니다.

## 1. 문서 개요

- **문서 버전:** 1.0
- **작성일:** 2026-09-23
- **상태:** 다음 개발 사이클 기준안
- **대상 제품:** StudySpace 웹 애플리케이션
- **선행 문서:** `docs/PRD.md`

이 문서는 기존 PRD의 학습 흐름(과목 → 강의노트 → 자료와 녹음 → AI 정리 → 연습)을 유지하면서, 현재 구현된 화면의 사용성 부족을 구체적인 UI·상태·연결성 요구사항으로 바꾼 후속 PRD다. UI 기반을 정리한 뒤 다음 개발 순서는 **Gemini 실연동**, 그 다음 **실제 녹음 기능**으로 한다.

## 2. 현재 화면 진단

현재 코드를 기준으로 로그인/회원가입, 대시보드, 3열 학습 공간, 노트 편집기, 자료·녹음·AI·연습 탭, 마이페이지 설정 화면이 구현되어 있다. 기능은 대부분 존재하지만 정보 우선순위와 상태 전환이 화면마다 달라 사용자가 “지금 무엇을 할 수 있고, 결과가 어디에 저장되었는지”를 한 번 더 추측해야 한다.

| 화면 | 현재 구조 | 발견한 부족점 | 개선 우선순위 |
|---|---|---|---|
| 인증 | 분할형 히어로 + 입력 폼 | 로딩·실패·재시도 상태와 입력 오류 위치가 일관되지 않음 | P1 |
| 학습 현황 | 오늘 수업, 이어서 공부하기, 활동, 퀴즈, 과목별 노트, 복습 카드 카드 묶음 | 정보 카드와 실행 카드의 위계가 같고, 카드별 다음 행동이 분산됨 | P0 |
| 과목·노트 공간 | 좌측 과목 rail + 노트 목록 + 편집기/도구 탭 | 좁은 화면에서 3열 전환 규칙이 불명확하고 선택 상태가 화면 이동 후 흔들릴 수 있음 | P0 |
| 노트 읽기·편집 | 보기/편집 모드, 저장 버튼, 노트·녹음·AI 정리·연습 탭 | 제목·저장 상태·현재 도구의 관계가 약하며 초안 보호가 명확하지 않음 | P0 |
| 자료 목록 | 파일/첨부 행 목록 | 파일명·크기·분석 상태·선택·삭제 액션의 열 기준이 없고 긴 이름 대응이 부족함 | P0 |
| 녹음 | 시작·일시정지·중지와 녹음 행 | 권한, 녹음 중, 업로드 중, 저장 완료/실패 상태가 같은 영역에 통합되지 않음 | P1 |
| AI 결과 | 생성 패널과 결과 카드 | 입력 출처, 진행률, 실패 이유, 재시도, 결과 저장 위치가 단계적으로 보이지 않음 | P0 |
| 퀴즈·플래시카드 | 생성/풀이 화면 | 목록→풀이→제출→복습의 뒤로 가기와 결과 반영 동선이 약함 | P1 |
| 마이페이지 | hash 기반 학교·학기·저장공간·계정 메뉴 | 설정 요약과 편집 폼이 분리되지 않고 섹션 전환 피드백이 약함 | P1 |

## 3. 목표와 비목표

### 목표

1. 모든 화면에서 **주요 행동 1개와 보조 행동**을 명확히 구분한다.
2. 카드, 표, 목록의 표현 규칙을 통일해 스캔 속도를 높인다.
3. 화면 전환 시 과목·노트·탭·스크롤·초안을 잃지 않는다.
4. 버튼 클릭이 반드시 화면 변화, 상태 변화, 이동 중 하나로 연결되도록 한다.
5. UI 기반을 정리한 뒤 Gemini와 실제 녹음 기능을 안전한 상태 머신으로 연결한다.
6. 노트는 기능을 과시하는 화면이 아니라 오래 읽고 다시 찾기 쉬운 학습 문서로 만든다.

### 비목표

- 이번 문서에서 백엔드 도메인 모델 전체를 재설계하지 않는다.
- 무거운 SPA 프레임워크로 전면 교체하지 않는다.
- Gemini 연동을 이유로 자동 생성 결과를 무검수로 게시하지 않는다.
- 녹음 단계에서 STT까지 동시에 완료하는 것으로 간주하지 않는다. STT는 후속 범위다.

## 4. 정보 구조와 이동 계약

```text
인증
 └─ 학습 현황
    ├─ 과목 선택
    │  └─ 노트 목록
    │     └─ 노트 읽기/편집
    │        ├─ 자료
    │        ├─ 녹음
    │        ├─ AI 정리
    │        └─ 연습(퀴즈/플래시카드)
    └─ 마이페이지(학교·학기·저장공간·계정)
```

- 현재 과목, 노트, 도구 탭은 URL 또는 hash에 복원 가능한 형태로 표현한다. 새로고침 후에도 같은 학습 맥락을 복원한다.
- 대시보드의 `이어서 공부하기`는 마지막 과목·노트·탭으로 직접 이동한다.
- 노트 도구 탭에서 뒤로 가면 노트 읽기 화면으로, 노트 목록에서 뒤로 가면 과목 화면으로 돌아간다. 브라우저 뒤로 가기와 앱 내부 뒤로 가기는 같은 규칙을 따른다.
- 저장되지 않은 편집 초안·진행 중 녹음·AI 생성이 있으면 이동 전에 인라인 경고와 `계속 이동 / 취소`를 제공한다.
- 이동 중에는 이전 화면을 비우지 않고 스켈레톤 또는 진행 상태를 보여 준다.

## 5. 공통 UI 규칙

### 레이아웃 토큰

- 기준 폭: 390, 768, 1024, 1440px. 모든 기준에서 가로 스크롤이 없어야 한다.
- 간격: 4/8/12/16/24/32px 체계. 카드 내부 기본 패딩은 20~24px.
- 모서리: 입력·행 10px, 카드 14px, 주요 컨테이너 18px.
- 색상은 `기본 텍스트 / 보조 텍스트 / 경계 / 배경 / 강조 / 성공 / 경고 / 오류` 토큰으로만 사용한다.
- 클릭 가능한 영역은 최소 44×44px, 키보드 포커스 링은 항상 보인다.

### 카드

카드는 아래 세 종류로 제한한다.

1. **요약 카드:** 숫자·상태·짧은 추세를 보여 주며 카드 전체를 클릭하지 않는다.
2. **작업 카드:** 사용자가 즉시 실행할 하나의 primary action을 가진다.
3. **상태 카드:** 분석·업로드·생성·동기화의 진행 상태와 재시도를 보여 준다.

모든 카드는 `헤더(이름·범위) → 핵심 값/콘텐츠 → 보조 정보 → 액션` 순서를 지킨다. 같은 카드 안에 또 다른 테두리 카드를 중첩하지 않으며, 데이터가 없을 때는 빈 상태 설명과 한 개의 CTA를 제공한다. 로딩·성공·실패·권한 없음 상태도 같은 카드 골격에서 교체한다.

### 버튼

- 한 화면 또는 한 카드에 primary 버튼은 최대 1개다.
- 버튼 라벨은 결과를 동사로 표현한다(`노트 만들기`, `자료 분석하기`, `다시 시도`).
- 버튼의 가로 크기는 글자 수에 따라 임의로 늘어나지 않도록 `min-width`, 좌우 padding, 줄바꿈 규칙을 공통 토큰으로 관리한다. 짧은 라벨도 지나치게 작아지지 않고, 긴 라벨도 화면 밖으로 밀려나지 않아야 한다.
- 버튼 높이는 기본 44px, 작은 보조 버튼은 36px 이상으로 고정한다. 버튼 내부 아이콘과 글자는 수직 중앙 정렬하며, 라벨은 기본 한 줄을 유지하되 모바일에서는 필요한 경우 자연스럽게 두 줄로 표시한다.
- 입력창 옆 버튼은 입력창 테두리에 붙여 하나의 긴 컨트롤처럼 보이게 만들지 않는다. 인풋과 버튼 사이에 최소 8px, 세로로 쌓이는 경우 최소 12px의 간격을 둔다.
- 폼의 입력 그룹과 하단 액션 영역 사이에는 최소 24px의 여백을 둔다. `저장`, `취소`, `삭제`가 연속될 경우 primary·secondary·danger 순서와 간격을 일관되게 적용한다.
- 클릭 후 300ms 안에 disabled/loading 상태 또는 화면 전환이 시작되어야 한다.
- 성공·실패는 버튼 옆 상태 텍스트나 toast로 알려 주며, 실패에는 재시도와 원인 안내를 함께 둔다.
- 동작하지 않는 장식용 버튼, 목적지가 없는 링크, `alert`만 띄우는 버튼은 배포 전에 제거한다.

## 6. 표·목록 UI 규칙

데이터를 비교하거나 반복적으로 관리하는 화면은 카드 나열 대신 표를 우선한다. 표에는 실제 `table`, `thead`, `tbody`, 행/열 헤더를 사용하고, 정렬·필터가 없으면 그 사실을 명시한다.

| 대상 | 기본 열 | 행 액션 | 모바일 변환 |
|---|---|---|---|
| 오늘 수업 | 시간, 과목, 수업명, 상태 | 수업 열기 | 시간 배지 + 세로 정보 + 한 줄 CTA |
| 과목 진행률 | 과목, 노트 수, 최근 학습일, 진행률 | 노트 열기 | 과목 요약 카드형 행 |
| 첨부 자료 | 파일명, 크기, 분석 상태, 선택, 동작 | 분석/삭제/열기 | 파일 메타 세로 행, 동작 하단 배치 |
| 녹음 | 이름, 길이, 생성일, 업로드 상태 | 재생/이름 변경/삭제 | 이름·길이 + 상태 칩 + 동작 행 |
| 퀴즈 기록 | 제목, 문항 수, 점수, 풀이일 | 다시 풀기/결과 보기 | 점수 강조 카드형 행 |
| 마이페이지 일정 | 요일, 시간, 과목, 강의실 | 편집/삭제 | 요일 그룹별 리스트 |

표 공통 요구사항:

- 헤더와 행의 수직 정렬, 숫자 우측 정렬, 상태는 색상만으로 구분하지 않는 텍스트 칩을 사용한다.
- 긴 파일명·강의명은 1~2줄 말줄임 처리하되 title/툴팁으로 전체 값을 확인할 수 있어야 한다.
- 행 hover뿐 아니라 키보드 focus와 선택 상태를 표시한다.
- 768px 이하에서는 고정 열을 남기지 않고 위 표의 모바일 변환 규칙으로 바꾼다. 1024px 이상에서는 필요한 경우 표 영역만 가로 스크롤한다.
- 빈 표는 “데이터가 없습니다”로 끝내지 않고 생성·연동·가져오기 CTA를 포함한다.

## 7. 화면별 개선 명세

### 7.1 학습 현황 대시보드

1. 상단에 `오늘의 학습 요약`과 현재 학습일을 배치한다.
2. 첫 행은 작업 카드 4개(`새 노트`, `이어서 공부`, `퀴즈 만들기`, `오늘 복습`)로 통일한다.
3. 두 번째 행은 오늘 수업 표와 과목 진행률 표를 배치한다.
4. 활동·퀴즈·복습 통계는 요약 카드로 내려 정보와 행동을 분리한다.
5. 카드 클릭이 아닌 명시적 버튼으로 과목·노트·퀴즈·플래시카드 목적지를 연결한다.
6. 데이터가 없을 때는 각각의 원인과 다음 행동을 제공한다(첫 과목 추가, 첫 노트 작성, 학교 연동).

### 7.2 과목·노트 작업 공간

- 데스크톱: `과목 rail 240px / 노트 목록 300px / 본문 flexible` 3열을 기본으로 한다.
- 태블릿: 과목 rail을 접고 과목 선택 드로어로, 노트 목록과 본문을 2열로 둔다.
- 모바일: `과목 → 노트 → 도구` 한 화면씩 이동하는 스텝형 흐름으로 바꾼다. 상단에는 현재 위치 breadcrumb와 뒤로 가기를 둔다.
- rail과 목록의 선택 행은 색상, 좌측 인디케이터, `aria-current`로 동시에 표현한다.
- 접기/펼치기는 150~200ms의 opacity/transform만 사용하고 콘텐츠 높이 점프를 막는다.

### 7.3 노트 읽기·편집

- **가독성 우선 원칙:** 노트 화면의 1순위는 읽기다. 카드, 배지, 버튼, 테두리를 콘텐츠보다 앞세우지 않으며, 장식용 그라데이션·과도한 그림자·중첩 패널을 사용하지 않는다.
- 노트 목록 행은 `제목 → 수정일 → 본문 미리보기` 순서로 구성한다. 미리보기는 Markdown 문법·이미지·코드 블록을 안전하게 정리한 일반 텍스트 1~2줄로 제한하고, 긴 내용은 말줄임 처리한다. 제목만 나열하는 목록보다 노트 내용을 빠르게 식별할 수 있어야 한다.
- 보기 화면의 `편집`과 `휴지통`은 제목 옆 하나의 정렬된 액션 그룹으로 배치한다. 편집이 주 액션으로 먼저 읽히게 하고, 휴지통은 보조·위험 액션으로 시각적으로 구분한다. 편집 화면에서는 보기 모드 액션 그룹을 중복 노출하지 않는다.
- 읽기 화면의 본문 폭은 한 줄 65~80자 내외로 제한하고, 제목·소제목·본문·인용·목록의 계층을 명확한 글자 크기와 행간으로 구분한다. 본문 행간은 1.65 이상, 문단 사이 간격은 행간보다 충분히 크게 둔다.
- 제목, 과목, 마지막 저장 시각, 편집/보기 상태를 본문 상단에 고정한다. 고정 영역은 작게 유지해 본문을 가리지 않는다.
- 노트 메타데이터는 한 줄 요약으로 정리하고, 파일명·생성 시각·태그를 여러 카드로 흩어 놓지 않는다.
- 편집 중에는 `저장 중 → 저장됨 → 저장 실패` 상태를 저장 버튼 주변에 표시한다.
- 노트·녹음·AI 정리·연습 탭은 동일한 탭 컴포넌트를 쓰고, 선택 탭과 콘텐츠 제목을 일치시킨다.
- 탭 변경 시 입력 초안, 선택 자료, 재생 위치를 보존한다. 초안이 있으면 탭 헤더에 점 표시를 한다.
- 보기 모드에서는 편집 도구를 숨기고 `편집` 하나만 노출한다. 편집 모드에서만 서식 도구를 제목 아래의 얇은 툴바로 보여 준다.
- 도구 모음은 아이콘만으로 의미를 전달하지 않고 짧은 라벨·tooltip·키보드 단축키를 제공한다. 자주 쓰지 않는 기능은 더보기 메뉴로 묶는다.
- 편집 영역에는 한 번에 하나의 주 작업만 강조한다. AI 생성, 녹음, 첨부, 퀴즈 패널을 본문 좌우에 동시에 펼쳐 노트 폭을 압박하지 않는다.
- 자동 저장·초안·충돌 상태는 본문 위에 큰 알림창으로 띄우지 않고 저장 버튼 주변과 상단 상태줄에 조용하지만 분명하게 표시한다.
- 긴 노트는 목차/헤딩 탐색을 제공하되 본문을 덮는 고정 사이드바 대신 접을 수 있는 목차 패널을 사용한다. 현재 읽는 헤딩을 강조하고 닫은 뒤에도 스크롤 위치를 보존한다.
- 빈 노트는 넓은 편집 공간과 한 문장 안내만 보여 준다. 예시 카드 여러 개나 장식 일러스트로 화면을 채우지 않는다.
- 편집 본문도 읽기 화면과 같은 글자 크기·행간·최대 줄 길이 기준을 따른다. 파일 첨부 컨트롤은 한 개의 명확한 선택 버튼과 파일명 상태로 표현하고, 브라우저 기본 컨트롤과 별도 라벨이 중복되어 보이지 않게 한다.
- 인용·AI 생성 문장은 본문과 구분되는 얇은 배경과 출처 링크만 사용한다. 결과를 일반 본문처럼 위장하지 않고 `AI 초안` 표식을 남긴다.
- 모바일에서는 본문 좌우 패딩을 20px 이상 확보하고, 하단 고정 툴바가 키보드와 겹치지 않도록 한다. 긴 제목과 파일명은 줄바꿈을 허용한다.

#### 노트 화면 품질 기준

| 점검 항목 | 기준 |
|---|---|
| 시선 흐름 | 제목 → 저장 상태 → 본문 → 보조 도구 순서가 한 번에 읽힘 |
| 밀도 | 한 화면에 primary CTA 1개, 보조 CTA 2~3개 이하 |
| 일관성 | 읽기/편집/AI 결과가 같은 본문 폭·타이포그래피 토큰 사용 |
| 장식 | 콘텐츠 이해에 기여하지 않는 테두리·배지·그림자 제거 |
| 복귀 | AI·녹음·퀴즈에서 노트로 돌아오면 스크롤·초안·선택 상태 복원 |
| 접근성 | 제목 계층, focus 순서, 명도 대비, 200% 확대에서 본문 손실 없음 |

### 7.4 자료와 녹음

- 자료는 위 표 규칙을 적용한다. 선택된 파일 수·예상 입력량·분석 가능 여부를 표 위 요약줄에 표시한다.
- 녹음은 `권한 요청 → 대기 → 녹음 중 → 일시정지 → 저장 중 → 저장됨/실패` 상태를 시각적으로 분리한다.
- 녹음 중에는 경과 시간, 일시정지, 중지, 현재 입력 상태를 한 영역에 둔다. 중지 시 이름 지정과 저장 확인을 거친다.
- 재생 행에는 재생/일시정지, 진행 바, 현재 시간/전체 시간, 재생 속도를 제공한다.

### 7.5 AI 정리·연습

- AI 생성 전에는 출처 파일명, 선택 문단, 문자 수/예상 입력량, 생성 종류를 확인 카드로 보여 준다.
- 생성 중에는 단계(`요청 준비 → 생성 중 → 결과 저장`)와 취소를 제공한다.
- 결과에는 생성 시각, 사용한 출처, 프롬프트 버전, 재생성·수정·노트에 반영 버튼을 표시한다.
- 퀴즈/플래시카드는 `목록 → 풀이 → 제출 → 결과 → 다시 풀기/다음 카드`의 단계와 뒤로 가기를 일관되게 유지한다.

### 7.6 마이페이지

- 좌측 설정 메뉴와 우측 콘텐츠 패널은 유지하되, 선택 섹션을 URL hash로 복원한다.
- 각 섹션 첫 부분에 현재 설정 요약 카드를 두고, 편집 폼은 그 아래에 둔다.
- 학교·학기 연동은 `입력 → 미리보기 → 확인 → 완료` 4단계로 표현하며 대시보드 과목/시간표와 연결한다.
- 저장·삭제·계정 변경은 확인 메시지, 성공 상태, 실패 재시도를 동일 컴포넌트로 처리한다.
- 폼은 `라벨 → 설명/도움말 → 입력 컨트롤 → 오류/상태 메시지` 순서로 세로 배치한다. 라벨과 입력창, 입력창과 다음 필드 사이에 충분한 여백을 둬 서로 붙어 보이지 않게 한다.
- 학교 검색·시간표 추가처럼 인풋과 액션 버튼이 함께 있는 행은 2열 grid를 사용하되, 인풋은 남은 공간을 채우고 버튼은 고정된 토큰 폭을 사용한다. 버튼 글자 길이에 따라 인풋이 튀거나 버튼이 과도하게 커지지 않아야 한다.
- 버튼이 입력창의 우측 테두리를 침범하거나 인풋 안쪽에 겹쳐 보이는 배치는 금지한다. 모바일에서는 인풋 아래에 버튼을 전체 폭 또는 최소 44px 높이로 배치한다.
- 설정 저장 버튼은 섹션 하단에 고정된 일관된 액션 영역에 두고, 취소·초기화·삭제와 시각적 위계를 분리한다. 저장 중에는 버튼 너비를 유지한 채 라벨만 로딩 상태로 바꾼다.
- 긴 버튼 라벨(예: `학교 정보 불러오기`, `연동한 학교 해제`)은 임의 축약하지 않고 충분한 최소 폭을 확보하며, 390px에서는 세로 배치로 전환한다.
- 오류 메시지는 버튼과 인풋 사이에 끼워 넣어 레이아웃을 밀어내지 않고 해당 필드 바로 아래에 표시한다. 오류가 사라져도 주변 컨트롤의 위치가 크게 점프하지 않도록 메시지 영역을 예약한다.
- 설정 섹션 사이에는 최소 32px의 수직 여백을 두고, 서로 다른 작업(학교 연동/계정 삭제)을 같은 카드나 같은 버튼 그룹에 섞지 않는다.

## 8. 화면 전환 및 상태 계약

모든 비동기 기능은 `idle → loading → success | error` 상태를 가지며, 사용자 입력이 있는 기능은 `dirty`, 외부 충돌은 `conflict`, 네트워크 단절은 `offline`을 추가한다.

- 전환 애니메이션은 150~200ms, transform/opacity만 사용한다. `prefers-reduced-motion`에서는 즉시 전환한다.
- 화면 진입 후 첫 제목 또는 주요 컨트롤로 focus를 이동하고, 모달 닫힘 후 이전 트리거로 focus를 복귀한다.
- 진행·성공·실패는 `aria-live="polite"` 영역에도 전달한다.
- 목록→상세→목록으로 돌아올 때 스크롤 위치와 선택 행을 복원한다.
- 새로고침·토큰 만료·네트워크 실패 시 사용자가 작성한 노트와 선택 자료를 버리지 않는다.

## 10. 다음 개발 단계 A — Gemini 실연동

UI 기반 개선 완료 후 Gemini 연결을 실제 provider 흐름으로 전환한다. 모델명과 API 키는 코드에 하드코딩하지 않고 환경 설정으로 관리한다. 개발 환경에서는 mock 플래그를 명시하고, 운영에서는 mock 결과가 노출되지 않도록 한다.

### 범위

- 요약, AI 노트, 주관식 문제, 퀴즈, 플래시카드, 마인드맵/인포그래픽 생성 API 연결
- 선택 자료의 스냅샷, 입력 문자 수, 프롬프트 버전, 생성 시각을 결과 메타데이터로 저장
- timeout, 재시도, 동시 요청 제한, 입력 길이 제한, 사용량 기록, provider 오류 매핑
- 결과를 노트에 반영하기 전 미리보기·수정·취소 제공

### Gemini UI 상태

1. 생성 전: 출처와 예상 입력량 확인, 개인정보/외부 전송 안내
2. 실행 중: 단계형 진행 상태와 취소
3. 성공: 출처·생성 시각·재생성·노트 반영
4. 실패: 사용자에게 이해 가능한 원인, 재시도, 자료 줄이기 안내
5. provider unavailable: mock으로 조용히 대체하지 않고 명시적인 사용 불가 상태

### Gemini 완료 기준

- 실제 API 키가 있는 staging에서 6개 생성 유형이 각각 성공/실패/timeout을 표시한다.
- 10MB 또는 입력 제한을 넘는 자료는 실행 전에 차단한다.
- 생성 결과에 사용 출처와 프롬프트 버전이 남고, 노트 반영 전 사용자가 수정할 수 있다.
- 같은 요청 재시도 시 중복 결과를 무분별하게 만들지 않고 기존 생성 상태를 갱신한다.
- mock과 실제 결과는 배지와 환경 설정으로 구분된다.

## 11. 다음 개발 단계 B — 실제 녹음 기능

Gemini 연동 안정화 다음에 브라우저 `MediaRecorder` 기반의 실제 녹음을 구현한다. STT는 이번 단계에서 제외하고 녹음 파일의 생성·저장·재생을 완료한다.

### 범위

- 권한 요청과 거부 안내, 브라우저별 MIME 타입 fallback
- 한 노트당 활성 녹음 1개, 시작·일시정지·재개·중지·이름 지정·저장
- chunk 업로드와 재시도/재개, 새로고침·탭 전환 시 진행 중 상태 보호
- 60분 hard stop, 파일 크기 제한, 저장 실패 복구
- 파형 또는 입력 상태 표시, 구간 이동 재생, 0.75/1/1.25/1.5배속

### 녹음 완료 기준

- 실제 마이크로 권한 승인 후 10초 이상 녹음하고 새로고침 뒤에도 저장 파일을 재생할 수 있다.
- 권한 거부, 지원하지 않는 MIME, 업로드 실패, 저장공간 부족을 각각 설명하고 재시도 경로를 제공한다.
- 녹음 중 다른 노트로 이동할 때 손실 없이 복귀하거나, 사용자가 명시적으로 폐기할 수 있다.
- 60분에 자동 종료되고 파일과 메타데이터(이름·길이·생성일·상태)가 녹음 표에 표시된다.
- 키보드로 시작/일시정지/중지/재생을 조작할 수 있고, 녹음 상태가 screen reader에 전달된다.

## 13. 성공 지표와 Definition of Done

- 주요 작업(새 노트, 이어서 공부, 자료 분석, 퀴즈, 복습)이 첫 화면에서 1회 클릭으로 시작된다.
- 화면 이동 후 과목·노트·탭·초안이 100% 보존된다.
- 기능 연결성 표의 모든 시작 액션에 성공·실패·재시도 결과가 존재한다.
- 표와 카드가 390px에서 겹치거나 가로로 잘리지 않는다.
- 200% 확대, 키보드 탐색, reduced motion에서 핵심 흐름을 완료할 수 있다.
- Gemini staging의 생성 성공률·실패 원인·사용량을 기록할 수 있다.
- 실제 녹음 파일을 저장하고 새로고침·재생·실패 복구까지 확인할 수 있다.

## 14. 미결정 사항
